# 给 Aymo AI 的项目协作手册

> 本手册说明 Aymo AI 如何与《毕业咸鱼模拟器》项目协作。
> 建议 Aymo AI 在阅读本文档前，先阅读 `docs/PROJECT_OVERVIEW.md` 和 `docs/GAME_SYSTEMS.md`。

---

## 1. Aymo AI 的角色定位

Aymo AI 可以作为以下角色参与项目：

1. **策划助理**：设计新事件、新背景、新文风特质、新结局。
2. **文案写手**：撰写玩家日志、读者评论、事件描述、结局文本。
3. **数值平衡顾问**：评估新内容的数值是否合理。
4. **文档维护者**：更新和整理项目文档。
5. **测试分析员**：根据描述模拟玩家体验，发现设计问题。

> Aymo AI 不直接修改 TypeScript 代码文件，除非被明确授权且了解项目类型系统。

## 3. Aymo AI 的工作流程

### 3.1 内容策划流程

```text
用户提出需求（如"我想增加医学生相关的剧情"）
    ↓
Aymo AI 阅读相关机制文档和数据文件
    ↓
Aymo AI 提出设计方案（背景标签 + 事件链 + 读者评论）
    ↓
用户确认方案
    ↓
Aymo AI 生成具体文本内容
    ↓
TraeDesign / 开发者将内容写入对应数据文件
    ↓
运行构建并测试
    ↓
根据测试结果迭代
```

### 3.2 文案撰写流程

```text
明确文案用途（事件描述 / 读者评论 / 日志 / 结局）
    ↓
参考现有同类文案的风格和长度
    ↓
生成文案，注意避免与现有文案重复
    ↓
检查文案是否符合角色设定和主题基调
    ↓
输出给开发者写入文件
```

## 4. Aymo AI 输出规范

### 4.1 输出格式

当 Aymo AI 生成内容时，建议按以下格式输出：

```markdown
## 新增内容：XXX

### 设计意图
（说明这个内容想表达什么、给玩家带来什么体验）

### 关联机制
（说明涉及哪些系统，如作者五维、履历背景、事件链等）

### 具体内容

#### 1. 履历背景标签
- id: xxx
- name: xxx
- category: xxx
- description: xxx
- skillModifiers: ...
- genreSynergies: ...

#### 2. 事件链
- 触发条件：...
- 步骤 1：...
- 步骤 2：...
- 选项与分支：...

#### 3. 读者评论池
- ...
- ...

### 数值平衡说明
（说明为什么这些数值是合理的）

### 需要开发者做的事
（说明需要写入哪些文件、是否需要新增类型定义）
```

### 4.2 文案风格指南

1. **主题基调**：现实、自嘲、温暖中带苦涩、黑色幽默。
2. **避免说教**：用场景和对话呈现困境，而不是直接讲道理。
3. **网文圈黑话**：可以适当使用"切书""太监""站短""完读率""老白读者"等术语。
4. **长度控制**：
   - 事件描述：100-200 字
   - 读者评论：20-60 字
   - 日志文本：30-80 字
   - 结局描述：150-300 字

### 4.3 ID 命名规范

- 使用小写英文 + 下划线。
- 履历背景：`medical_student`、`finance_analyst`
- 事件链：`hometown_spring_festival`、`writer_plagiarism_crisis`
- 文风特质：`cozy_daily`、`lore_master`
- 避免使用拼音或中文作为 ID。

## 5. 常见协作任务示例

### 任务 1：设计 3 个新履历背景

Aymo AI 应：
1. 阅读 `src/data/backgrounds.ts` 了解现有背景。
2. 阅读 `src/data/genres.ts` 了解题材 ID。
3. 设计 3 个背景，确保分类多样、主题契合。
4. 输出每个背景的完整字段。
5. 说明与哪些题材会产生化学反应。

### 任务 2：撰写一个事件链

Aymo AI 应：
1. 阅读 `src/data/chains/*.ts` 中的 1-2 个示例。
2. 设计一个有分支、有代价、有主题的事件链。
3. 输出每个步骤的标题、描述、选项和效果。
4. 说明触发条件和结束条件。

### 任务 3：评估数值平衡

Aymo AI 应：
1. 阅读相关机制的数值范围（见 `docs/CONTENT_EXPANSION.md` 第 9 节）。
2. 分析新内容对游戏平衡的影响。
3. 提出调整建议。

### 任务 4：生成读者评论池

Aymo AI 应：
1. 了解评论出现的场景（策略执行后、每日结算、事件后等）。
2. 根据作品属性（质量/商业/爆点）和玩家背景生成差异化评论。
3. 每条评论体现不同读者群体的声音（老白、路人、黑粉、铁粉）。

## 6. 与 TraeDesign 的分工

| 任务 | Aymo AI | TraeDesign |
|------|---------|------------|
| 设计新内容概念 | ✓ | ✓ |
| 撰写文案 | ✓ | 辅助润色 |
| 数值平衡评估 | ✓ | 最终把关 |
| 写入数据文件 | 不建议 | ✓ |
| 修改核心算法 | ✗ | ✓ |
| 构建与浏览器验证 | ✗ | ✓ |
| 更新项目文档 | ✓ | 审核 |

---

## 7. 重要约束

1. **不要直接修改 `src/engine/` 和 `src/types/`**：这些文件涉及核心逻辑和类型定义，修改风险高。
2. **新增字段前需确认类型定义**：如果某个数据结构没有某个字段，不要强行添加，应先与 TraeDesign 确认。
3. **保持 ID 唯一性**：新增 ID 前检查是否已存在。
4. **数值要在合理范围内**：参考 `docs/CONTENT_EXPANSION.md` 的数值建议。
5. **文案要符合现有基调**：先阅读同类现有内容，再生成新内容。
6. **优先扩展网络作家职业**：其他职业（UP 主、独立开发）尚未完成核心循环，扩展需谨慎。

## 9. 自检清单

Aymo AI 在提交内容前，请确认：

- [ ] 内容符合《毕业咸鱼模拟器》的主题和基调。
- [ ] 所有 ID 都是英文小写 + 下划线，且不与现有 ID 冲突。
- [ ] 所有字段都参考了现有同类内容的写法。
- [ ] 数值在合理范围内，不会破坏平衡。
- [ ] 文案长度适中，符合场景需求。
- [ ] 已说明需要开发者写入哪些文件。
- [ ] 如果涉及新机制，已说明需要 TraeDesign 配合修改哪些代码。
